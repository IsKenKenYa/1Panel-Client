# 沉浸式方案对比与选型（IMM-01）

## 基本概念

| 概念 | 说明 |
| --- | --- |
| 状态栏 | 顶部系统信息栏（电量、时间等） |
| 导航区域 | 分底部导航和三键导航，底部导航一般表现为导航条 |
| 避让区 | 状态栏和导航区域在沉浸式布局下的统称 |
| 安全区 | 避让区之外的区域，UI 元素默认在此布局 |
| 沉浸式布局 | 布局范围从安全区扩展到整个窗口（包括状态栏和导航条区域），**状态栏和导航条仍然可见**，只是布局不再避让它们。≠ 隐藏状态栏和导航条 |

> **常见误解**：很多开发者认为"沉浸式"就是状态栏和导航条都隐藏。实际上沉浸式布局下系统栏仍然显示，布局延伸到避让区，需要手动做避让处理。隐藏系统栏是独立操作（`setSpecificSystemBarEnabled`），与沉浸式布局是两个不同的概念，可以配合使用。

## 三种方案详解

### 方案 A：组件页面沉浸（组件级）

**核心 API**：`.ignoreLayoutSafeArea()` + `.height(LayoutPolicy.matchParent)`

**原理**：页面背景与布局均扩展至顶部状态栏和底部导航条。

**特点**：
- 背景与内容均扩展至避让区
- 每个页面均需单独配置
- 内容易与避让区元素冲突，需手动处理避让

**适用场景**：需组件内容完全覆盖屏幕的场景

### 方案 B：安全区域拓展（组件级）

**核心 API**：`.expandSafeArea([SafeAreaType], [SafeAreaEdge])`

**原理**：将组件的安全区域延伸至状态栏或导航条区域，同时保持子组件在安全区内布局，无需额外避让处理。

**特点**：
- 仅背景扩展至避让区，内容默认在安全区
- 支持指定系统避让区域类型（SafeAreaType）和延伸方向（SafeAreaEdge）
- 子组件仍在安全区内布局，无需额外避让处理
- 滚动内容无法延伸至避让区

**适用场景**：需要指定延伸区域类型的局部延伸场景（上下不同色、背景图、视频背景）

**限制**：
- 组件必须与安全区域边界重合才生效
- 不能配置固定宽高（百分比除外）
- 父容器是滚动容器时无效

### 方案 C：窗口沉浸式显示（窗口级）

**核心 API**：`setWindowLayoutFullScreen(true)`

**原理**：设置窗口为沉浸式布局，页面布局范围从安全区域扩展为整个窗口（包括状态栏和导航条）。

**特点**：
- 全局统一生效，所有页面均开启沉浸式布局
- 适配逻辑集中
- 需手动计算避让区高度，处理所有内容避让

**适用场景**：应用所有页面均需实现沉浸式的场景

## 方案对比总表

| 对比维度 | 方案 A 页面沉浸 | 方案 B 安全区域拓展 | 方案 C 窗口沉浸显示 |
| --- | --- | --- | --- |
| 级别 | 组件级 | 组件级 | 窗口级 |
| 背景/内容 | 背景与内容均延伸 | 仅背景延伸 | 背景与内容均延伸 |
| 避让处理 | 需手动处理 | 无需（内容在安全区） | 需手动处理 |
| 配置粒度 | 每页单独配置 | 每页单独配置 | 全局一次配置 |
| 滚动支持 | 支持 | 不支持延伸 | 支持 |
| 指定方向 | 不支持 | 支持（TOP/BOTTOM/LEFT/RIGHT） | 不支持 |

## 选型建议

| 需求 | 推荐方案 |
| --- | --- |
| 上下颜色不同，分别延伸 | 方案 B（`.expandSafeArea()`） |
| 需要内容也延伸到避让区 | 方案 A（`.ignoreLayoutSafeArea()`） |
| 全应用统一沉浸式 | 方案 C（`setWindowLayoutFullScreen`） |
| 游戏/视频全屏，隐藏系统栏 | `setSpecificSystemBarEnabled`（无需 setWindowLayoutFullScreen） |
| 自由窗口标题栏沉浸 | 单独适配（见 imm-05-practical-cases.md） |

> 窗口沉浸式效果由不同页面的沉浸实现，页面沉浸式效果由不同组件的沉浸策略组合而成。建议通过组件沉浸方案为每个页面配置不同的沉浸策略。
