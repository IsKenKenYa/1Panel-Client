# 碰一碰 Skill 验收清单

供人验收使用。各 `test-case-*.md` 只写本场景重点，通用项引用本文件。

**不算本 Skill 自动通过**（只进完成报告人工清单）：真机碰一碰、设备碰一碰开关、同账号联调、手动签名、域名托管。

## 行为与交付标准（S1–S21）

| ID | 标准 |
|---|---|
| S1 | 按「核验 → 确认 → 改码 → 检查 → 报告」推进；缺项靠引导补，不靠多轮试错 |
| S2 | SDK 按类型区分目标版本：仅链接 20+；含文件先定是否精准再定 22+ 或 26+；禁止未问是否精准就按 API 20 统一升级或中止，或把文件侧目标定为 20 |
| S3 | 先确认再改码；未答清不修改代码 |
| S4 | 文件侧落实 URI 宿主来源与类型标识（`utd`）；不用空值或未转换的无效 path；发送不套接收默认目录当根路径 |
| S5 | 增量不新建第二套管理类/监听 |
| S6 | 报告含人工清单；未就绪不声称完成 |
| S7 | 回调不做下载或重 IO；数据在监听前备好 |
| S8 | 提问范围与已定类型一致：仅文件不问链接项，仅链接不问文件项、电脑接收与精准 |
| S9 | 按类型使用对应实现（`assets/file` / `link` / `both`），不混入多余分支 |
| S10 | 可分享页显示时注册、离开时注销监听 |
| S11 | 注入位置经确认；不另起工程、不替换架构 |
| S12 | 须打开对应 assets 模板；读不到则中止，禁止凭记忆重写 |
| S13 | 链接：云侧不进工程；确认后才接入口跳转 |
| S14 | 不臆造选择逻辑；可选字段与多文件仅确认后实现 |
| S15 | 完成报告字段齐全（含 URI 来源；电脑接收+精准时含 UI 与落点） |
| S16 | 能编译则通过；不能则写明，不谎称通过 |
| S17 | 升 26 须打开 SDK 字段片段（`sdk-profile-snippet.json5`），写入三段式版本号 `"26.0.0"`；禁止错误括号写法 |
| S18 | 电脑接收时接收能力声明（`capabilities`）与发送侧类型标识（`utd`）一致；单次最多接收文件数不超过 5（`maxSupportedCount`） |
| S19 | 电脑接收且精准均为是时，先读实际 UI 再确认接收落点（含自定义） |
| S20 | 是否有可分享内容（`canShare`）不按设备类型返回 false；精准未命中回退全量取数 |
| S21 | 接线只打开与类型对应的一份挂载示例，不打开另外两份，不把多份内容拼进同一页 |
| S22 | 阶段 0 预检查记录回滚能力预判（git 版控？）与基线快照（git status / HEAD 或关键文件清单） |
| S23 | 变更写入后失败或用户放弃时，依据 S22 预判与快照执行回滚：git → `git checkout` 还原；非 git → 输出已改文件清单 + 每处改动摘要供人工还原。已拷入资产若本次新增一并还原/列出。回滚后输出原因与清单 |
| S24 | 挂载冲突预检：目标页已有 `knockShare` 监听 → 合并到同一 Manager；生命周期钩子已被占用 → 追加而非覆盖 |

## 完成报告字段（S15）

| 字段 | 要求 |
|---|---|
| 修改摘要 | 新增/修改文件列表；首次或增量 |
| 分享类型 | 文件 / 链接 / 两者 |
| 引导确认摘要 | 按类型填写；含 SDK 目标版本与 URI 来源等；仅文件不写域名；仅链接不写文件 uri、电脑接收与精准；电脑接收与精准都开时含 UI 与落点 |
| 挂载点 | 页面路径 + 生命周期钩子；both 包另写 `KnockShareMode` |
| 验证结果 | 静态检查 / 编译结果；无构建能力则写明 |
| 人工清单 | 设备开关、同账号、碰应用窗口、双机联调；含链接时再列签名、域名、云侧配置等 |
| 已知限制 | 如回调超时、精准未命中回退等 |
