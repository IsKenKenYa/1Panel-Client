# 用例：SDK 过低 / 已是 20 须先定目标再升级

## 目标

仅链接按 API 20+ 判断和升级。含文件时先确认是否精准，再决定升到 API 22+ 或 26+。文件侧禁止落到 20。升 26 用三段式 `"26.0.0"`。

## 前置

- 工程视为低于目标（如 5.0.0(12)）或已是 6.0.0(20) 含文件未问精准
- 本 Skill `assets/sdk-profile-snippet.json5`、`references/sdk-version.md` 可读

## 步骤

1. 用 [test-prompts.md](test-prompts.md) 场景 3 / 3b 触发
2. 观察提问顺序与是否改 `build-profile.json5`

## 本场景重点标准

见 [acceptance-checklist.md](acceptance-checklist.md)：S2, S17

## 通过标准

- [ ] 工程 SDK 低于目标时：先提问/确认升级，未获确认前不改 `build-profile.json5`、不注入 Manager（S2）
- [ ] **仅链接**：目标 **API 20+**；拒绝升级 → 停止改码；不问 Q8（S2）
- [ ] **类型含文件且未说明 Q8**：先问是否精准，本轮不夹杂 Q3/Q7/接收落点（S2）
- [ ] Q8 = yes：目标 **API 26+**；写入 **`"26.0.0"`**，不得 `"7.0.0(26)"`；须打开 SDK 字段片段；拒绝升 26 → 不做精准，改按 **API 22+**（S2, S17）
- [ ] Q8 = no：目标 **API 22+**，写入 `"6.0.2(22)"`；拒绝升 22 → 停止改码（S2）
- [ ] 含文件时不要再用「升到 20 只发文件」路径（S2）
