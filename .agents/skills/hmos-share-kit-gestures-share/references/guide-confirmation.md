## 环节级约束（唯一来源，跨提问轮次与最终报告生效）

两条约束以本节为准，SKILL.md 不复述；下文「提问总则」与「按类型提问矩阵」中的相关内容均在本节之下展开。

- **类型门控**：类型（Q1）先于一切类型相关问题——类型未定，本轮只问类型；类型一经确认，问题集锁定，集外问题（含全部子项）禁止出现在后续任何一轮与最终报告。
- **输出红线**：仅文件 → 不输出链接项（App Linking、域名、skills 配置、applinking）；仅链接 → 不输出文件项（可分享范围、文件 uri、addRecord）；本条只约束 skill 的输出，开发者主动提及另一类型时正常受理（按增量流程）。

## 提问总则（三层分流）

问题分三层，**能不问就不问**：

| 层级 | 处理方式 |
|------|----------|
| 必问（M） | 无默认值且无法从代码/配置推断 → 一轮问完 |
| 探测后确认（D） | 先代码探测/读配置；唯一结论 → 直接采用并写报告；多候选 → 附候选让开发者选；零候选 → 降级为必问 |
| 默认值（F） | 直接采用默认，完成报告声明；开发者不满意再改 |

补充规则：
1. 先定类型（Q1）再按类型提问（见「环节级约束·类型门控」）：类型未定 → 本轮只问 Q1；类型一经确认 → 问题集按「按类型提问矩阵」锁定，集外问题（含全部子项）禁止出现在后续任何一轮。
2. 选择题优先，在锁定的问题集内一轮问完；附探测候选时须带证据（文件路径 / 字段名），候选仍须开发者确认。
3. 禁止跳过引导直接改码；仅当开发者明确「由 skill 自行决定 / 你来定」才可对未答项自决，并在完成报告中写明自决项。
4. 增量场景只问本次新增类型的问题：新增类型 = 目标类型 − 既有实现已具备的能力；用户请求未指明新增 → 必问「本次要补哪种类型」；补文件 → 只问 Q3；补链接 → 只问 Q4；补成两者 → 加问 Q5。
5. 向开发者提问与确认时，禁止携带题号（Q1-Q5）、层级记号（M/D/F）与「绑定」话术；下文交互点标签仅内部使用，直接问问题内容本身（如「需要分享哪些文件、文件地址如何获取？」而非「请回答 Q3」）。

## 默认值表（F 层，不问，报告声明）

| 项 | 默认值 |
|----|--------|
| Manager/Provider 位置 | 挂载页所在模块 `src/main/ets/share/`；无挂载页信息 → `entry` 主模块 |
| utd 来源 | 按文件扩展名 `getUniformDataTypeByFilenameExtension`，每条文件运行时单独算；工程内已声明自定义 UTD 时以业务值为准 |

## Q2 挂载页探测路径

按顺序探测，命中即止：
1. 用户需求话术（「我的相册页想支持一抓一放」→ 相册页）
2. 扫描页面清单（`@Entry` 页、NavDestination 路由表），定位**渲染了可分享数据的页面**（数据在哪展示，手势就在哪生效）
3. 唯一候选 → 直接定 + 报告声明；多候选（如列表页+详情页都有数据）→ 附候选问一次；零候选（无可分享数据源）→ 转必问，并确认数据来源

## Q3 文件数据源细则（仅当类型含文件）

探测优先（提问前先搜工程，附候选让开发者确认）：
- 数据模型：含 uri / filePath / path 字段的 model 类
- 勾选状态：`selected` / `checked` / `isSelect` 等字段或状态数组
- 既有转换：`getUriFromPath` / `fileUri` 的既有用法（说明宿主习惯）
- 沙箱写入：`filesDir` / `cacheDir` 使用处

| 必确认项 | 确认什么 | 核验要点 |
|----------|----------|----------|
| 可分享范围 | 哪些文件可分享？勾选子集 / 全量 / 焦点项？是否可能多文件？ | 禁止臆造 `selected*`；可能 >1 → `addRecord` 循环；无有效项 → `canShare()===false` |
| uri 获取 | 已是 `file://` 字段？沙箱 path 需 `getUriFromPath`？在哪转？ | 禁止裸 path 当 uri；优先应用沙箱 URI（免额外授权）；多文件每条自有 uri |

utd 与可选字段**不问**，按默认值表处理。数据源无法落实且未获自决授权 → 追问或中止文件接入，禁止空字符串 / 假 URI 糊弄。

## Q4 链接类细则（仅当类型含链接）

| 必确认项 | 确认什么 | 核验要点 |
|----------|----------|----------|
| 域名 | 已完成域名关联的正式域名？ | 禁止把 `www.example.com` 当生产配置写入并宣称联调完成 |
| path / query | 链接路径与业务参数？ | `content` 为完整 `https://` 链接，可带业务 query |
| 落地页 | 接收侧跳转目标页？ | 可附路由表候选；与宿主现有路由风格一致；Ability 只落盘 uri，由入口页触发跳转 |

**域名未就绪 → 两阶段，不阻塞**：
- 阶段 1（域名未确认也可立即做）：发送侧 Provider + `incomingUri` 落盘骨架；`module.json5` skills 的 host 留 `TODO` 占位并在报告高亮
- 阶段 2（域名确认后）：回填 host 与 `content` 域名；TODO 未清除前禁止宣称「直达可用」
- 云侧（AGC 关联、部署 `applinking.json`、正式签名）始终列人工清单

未确认 Q4 前，不得写入生产 App Linking 并宣称直达可用。

## Q5 模式切换细则（仅当类型=两者）

both 包 `enable(ctx, GestureShareMode, provider)` 每次需传 `GestureShareMode`，须确认切换规则：
- 固定一种？（本页面只分享文件，链接由其他页面负责）
- 按 Tab / 分栏切换？（切换时重新 `enable` 传新 mode）
- 按内容动态判断？（当前展示链接 → LINK，否则 FILE）

未确认时禁止臆造切换逻辑。

## 基线裁决（仅当前置步骤 Step 2 记录了相似分享实现）

探测到未接线的相似分享实现（如自写 `ShareModel.ets`，含注释掉的监听痕迹）→ **不归增量**：无已注册监听，增量流程（不建第二套 / diff 升级 / 只问新增类型）全部不适用；增量判定唯一标准 = 是否存在已注册监听。引导确认轮附文件路径与证据问一次：

- **按标准模板新建**：既有文件保留不动，完成报告「已知限制」附路径注明；既有文件恰与模板目标路径同名时，新建文件另选落盘目录并在报告中说明，禁止覆盖保留文件
- **基于既有实现改造**：完整引导确认（Q1-Q5 不省问——半成品从未完成过引导确认，禁止套用增量省问逻辑），按错误处置表 E8（1）授权迁移重构，报告列明被替换内容与被删除文件
- 未获回应 → 追问一次；仍无回应 → 采用「按标准模板新建」（安全默认，不动既有文件），完成报告自决项中声明

## 云侧边界（不问、不改工程）

`appIdentifier` 与网站 `applinking.json` 属云侧（AGC + `https://<domain>/.well-known/applinking.json`）：
- 不作为端侧问答项，不写入 `module.json5` / Ability / ets 或任何工程文件
- 只列入人工清单；可出示 `assets/app-linking-tools/applinking.json` 供部署，但禁止拷入工程
