# 应用冷启动内存对比：旧版 vs 新版

> **纯净产物**：本报告只含结构化数据表 + 步骤 3/4/5 脚本产出的归因字段；不含"共性根因/关键发现/总体结论/修复建议小结"等发散分析（综述统一放综合防劣化分析报告）。详见 comparison-report-guide.md「报告纯净性」。

## 一、深度分析结果

> 对第五章 Top10 劣化 SO 按其 type_name 明细分发到步骤 3/4/5 后，将各步骤归因结论合并于此。逐个 SO 列出引用链/根因推断/修复建议/**严重性定级（<span style="color:#e74c3c">高</span>/<span style="color:#e6a700">中</span>/<span style="color:#3498db">低</span>）**；未触发深度分析时注明「无 SO 进入深度分析」。**各小节内 SO 按最终严重性（含降级后的结果）从高到低排列。**

> **严重性定级**：<span style="color:#e74c3c">高</span>=差值≥10MB 或 增长比例≥50% 或 新增（旧版=0）；<span style="color:#e6a700">中</span>=差值3–10MB 或 比例20–50%；<span style="color:#3498db">低</span>=差值<3MB 且 比例<20%。取差值档与比例档中更严重者。**降级规则**：结合源码分析后，若劣化来自自身业务场景的新增功能（如新增页面/模块/能力带来的正常内存增长）或其他无需修复的场景（如测试桩、调试代码、已知可接受的框架开销），严重性可降为<span style="color:#3498db">低</span>。
