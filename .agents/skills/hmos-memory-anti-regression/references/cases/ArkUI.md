# ArkUI 劣化案例模式（页面 / 组件 / 滚动）

> 本文档定义 ArkUI 维度劣化的典型案例模式，供劣化点根因匹配使用。匹配到下列案例时：可引用案例的根因推断并标注出处（如「见 ArkUI.md · 页面 一、预加载不可见页面」）；未匹配到时：根因列写「未匹配案例库，需人工核查」，不给修改建议。

## 页面

### 预加载不可见Tab页面

#### 案例模式描述

与用户使用意图无关、尚未访问的整个页面被提前加载。如某音乐app预加载 唱 Tab 页。这类劣化本质是**不可见页面的提前构建与驻留**，属时机不当的预加载，而非合理使用增长。

#### 匹配规则

1. **`libace_compatible.z.so` 内存劣化（数据规则）**：A/B 两版 so maps/native heap 对比中，劣化侧 `libace_compatible.z.so` 占用增长（ArkUI 兼容层 so，承载页面/组件构建）。
2. **arkui dumpview 工具对比两版本（核查规则）**：用 arkui dumpview 工具对比 A/B 两版本，确认新版本运行了 Tabs 的 `preloadItems` 方法、预加载了页面。检查要点：
   - dumpview 对比两版本，确认新版本执行了 Tabs 的 `preloadItems` 调用、预加载了不可见页面；
   - 预加载的页面是否在用户尚未访问时即被构建并常驻。

两条规则同时命中即确认：劣化源于预加载不可见 Tab 页面。规则 2 未发现 `preloadItems` 调用时，仅凭规则 1 不得下此结论，根因列写「未匹配案例库，需人工核查」。

### 冗余加载 Tabs 中间页面

#### 案例模式描述

Tabs 组件跨页面切换时，加载了中间页面。如 某新闻app从首页切换到娱乐页场景，默认滑动动画过程中加载中间体育页（大图 + 组件）。这类劣化本质是**切换动画过程触发的中间页加载**，属切换路径冗余。

#### 匹配规则

1. **`libace_compatible.z.so` 内存劣化（数据规则）**：A/B 两版 so maps/native heap 对比中，劣化侧 `libace_compatible.z.so` 占用增长（ArkUI 兼容层 so，承载页面/组件构建）。
2. **arkui dumpview 工具发现新版本加载中间页（核查规则）**：用 arkui dumpview 工具对比 A/B 两版本，发现新版本在 Tabs 切换过程中加载了不涉及的中间页面。检查要点：
   - dumpview 对比两版本，确认新版本在切换路径加载了用户目标页之外的中间页；
   - 中间页是否含大图/组件等重内容、随切换加载后常驻未释放。

两条规则同时命中即确认：劣化源于冗余加载 Tabs 中间页面。规则 2 未发现中间页加载时，仅凭规则 1 不得下此结论，根因列写「未匹配案例库，需人工核查」。

### Tabs 缓存数量过多

#### 案例模式描述

Tabs 组件多页面切换后，缓存的页面数过多不释放，未设置/设置过大的 maxCachedCount。如 8 个页签各 2 张大图 + 资讯流，全缓存不释放。这类劣化本质是**Tabs 缓存上限设置过大**，缓存不释放导致内存增长。

#### 匹配规则

1. **`libace_compatible.z.so` 内存劣化（数据规则）**：A/B 两版 so maps/native heap 对比中，劣化侧 `libace_compatible.z.so` 占用增长（ArkUI 兼容层 so，承载页面/组件构建）。
2. **arkui dumpview 工具对比两版本（核查规则）**：用 arkui dumpview 工具对比 A/B 两版本，发现新版本中 Tabs 未设置 `cachedMaxCount` 属性，导致缓存页面不释放。检查要点：
   - dumpview 对比两版本，确认新版本 Tabs 未设置 `cachedMaxCount` 属性；
   - 各页签是否含大图/资讯流等重内容、全缓存不释放。

两条规则同时命中即确认：劣化源于 Tabs 缓存数量过多。规则 2 未发现 `cachedMaxCount` 未设置时，仅凭规则 1 不得下此结论，根因列写「未匹配案例库，需人工核查」。

## 组件

### 长列表滚动不懒加载

#### 案例模式描述

滚动组件（如 List、Swiper）子组件多、复杂，没有使用懒加载，一次性全加载。如 某音乐 app 尚未显示到的歌词也会先加载，显示后也不销毁。这类劣化本质是**滚动组件全量加载**，应用 ForEach 而非 LazyForEach。

#### 匹配规则

1. **`libace_compatible.z.so` 内存劣化（数据规则）**：A/B 两版 so maps/native heap 对比中，劣化侧 `libace_compatible.z.so` 占用增长（ArkUI 兼容层 so，承载页面/组件构建）。
2. **源码阅读或 arkui dumpview 工具分析（核查规则）**：阅读源码或用 arkui dumpview 工具分析，确认滚动组件未使用懒加载（`LazyForEach` 或 `Repeat`）。检查要点：
   - 源码或 dumpview 确认滚动组件用 `ForEach` 全量加载而非 `LazyForEach`/`Repeat` 按需加载；
   - 列表项是否含复用图等重内容、全量构建常驻。

两条规则同时命中即确认：劣化源于长列表滚动不懒加载。规则 2 未发现滚动组件使用全量加载（未用 `LazyForEach`/`Repeat`）时，仅凭规则 1 不得下此结论，根因列写「未匹配案例库，需人工核查」。
