# 输出格式规范

向用户展示检查结果、修复方案、验证结论时，**必须使用 Markdown 表格**，禁止纯文本罗列。各环节的表格列定义如下。

## 表 1：规则集总览（Step 2a 展示）

| 列名 | 说明 |
|------|------|
| 规则集前缀 | 如 `@performance`，不带 `plugin:` 前缀 |
| 检查内容 | 该规则集覆盖的检查领域 |
| recommended | recommended 预设规则数，无则填 `—` |
| all | all 预设规则数，无则填 `—` |
| 全部规则 | 可经 `rules` 字段启用的规则总数（含预设内） |
| 典型使用场景 | 一句话场景说明 |

> 列名禁止出现 "schema"、"code_linter_schema.json" 等内部术语。

## 表 2：检查报告汇总（Step 4 解析后首先展示）

| 列名 | 说明 |
|------|------|
| 级别 | 🔴 error / 🟡 warn / 🔵 suggestion |
| 数量 | 该级别告警条数 |
| 说明 | 该级别涉及的主要规则（用顿号分隔），或"无" |

> 必须包含三行（error/warn/suggestion），数量为 0 时说明列填"无"。表格下方可附加涉及文件数、热点规则 TOP 数等补充信息，但补充信息不得替代本表。

## 表 3：问题清单（Step 4 解析后按文件展示）

| 列名 | 说明 |
|------|------|
| 文件 | 相对于工程根目录的路径 |
| 行:列 | 如 `42:8` |
| 级别 | 🔴 / 🟡 / 🔵（单个 emoji，不带文字） |
| 规则 | 完整规则 ID，如 `@performance/load-on-demand-check` |
| 描述 | 告警 message 原文 |

> 同一文件的多条告警合并为一个表格区块，文件名作为区块标题；不同文件用 `###` 分隔。禁止按规则跨文件聚合展示——用户定位问题时以文件为单位更直观。

## 表 4：QuickFix 探测结果（Step 5a 提取后展示）

| 列名 | 说明 |
|------|------|
| 状态 | ✅ 可自动修复 / 🔧 需手动处理 |
| 条数 | 该状态下的告警条数 |
| 规则 | `规则ID（N 条）` 格式，多条规则用换行或顿号分隔 |

> 必须包含两行（可自动修复 / 需手动处理）。某状态条数为 0 时仍保留该行，规则列填"—"。

## 表 5：修复方案（Step 5b 通过 question 工具呈现）

修复方案通过 `question` 工具的 `options` 呈现，不使用表格。但 `question` 的 `question` 字段描述必须引用表 4 的实际探测结果（可修复 X 条 / 需手动 Y 条 + 具体规则名），禁止笼统措辞。

## 表 6：修复验证结果（修复后重新检查时展示）

| 列名 | 说明 |
|------|------|
| 级别 | 🔴 error / 🟡 warn / 🔵 suggestion |
| 修复前 | 修复前的该级别数量 |
| 修复后 | 修复后的该级别数量 |

> 必须包含三行。若修复后出现新增告警（如被原告警遮蔽的 suggestion），在表格下方用一段文字说明新增告警的规则、条数及可能原因（如规则间遮蔽关系解除），不得隐瞒。

## 通用要求

| 要求 | 说明 |
|------|------|
| 禁止纯文本罗列 | 凡涉及多条目展示（告警清单、规则集、统计对比），必须用表格 |
| 禁止截断规则 ID | 规则列必须为完整 ID（含 `@前缀/`），不得缩写为 `quotes`、`foreach-args` 等 |
| 禁止省略级别行 | 表 2、表 6 必须含全部三个级别行，即使数量为 0 |
| 路径用相对路径 | 文件列相对于工程根目录，不输出绝对路径 |
| 数量为 0 时 | 数量列填 `0`，说明/规则列填"无"或"—"，不得省略该行 |

---

> 规则级别覆盖（`rules` 字段）属于配置范畴，详见 [配置参考](config-reference.md)。
