# 测试提示词

覆盖三大类别：基础功能（真机采集 / 本地解析）、边界条件（输出冲突 / 包名歧义）、错误处理（拉取超时 / 无设备）。

## 基础功能测试

### 测试场景 1：本地日志解析出图
**提示词**：
```
我有一份依赖图日志 app_dependency_graph.txt，帮我生成模块依赖可视化报告，输出到 dep_report.html
```
**预期输出**：
- 定位内嵌工具 scripts/modtree.exe，确认日志存在后执行 `modtree -o dep_report.html app_dependency_graph.txt`
- 以 stdout `[OK] 完成` 与 HTML:/Markdown: 路径判定成功
- 汇报统计（模块数/边数/循环组数）来自实际输出

### 测试场景 2：真机一键采集
**提示词**：
```
帮我采集抖音的模块依赖结果
```
**预期输出**：
- 推断包名 com.ss.hm.ugc.aweme 并反述确认；确认设备在线
- 专用输出目录执行 `modtree -bundle com.ss.hm.ugc.aweme`，超时 ≥120 秒
- 成功后汇报统计与产物路径，循环依赖主动提示

## 边界条件测试

### 测试场景 3：输出路径冲突
**提示词**：
```
把依赖报告输出到 report.html，我目录里已经有一个同名的 report.html 了
```
**预期输出**：
- 检测同名文件，先确认是否覆盖或建议换名，未确认不覆盖

### 测试场景 4：应用名无确定包名映射
**提示词**：
```
采集一下快手鸿蒙版的依赖
```
**预期输出**：
- 询问并确认包名，禁止对猜测包名直接执行 -bundle（采集属破坏性操作）

## 错误处理测试

### 测试场景 5：自动拉取超时
**提示词**：
```
采集超时了，工具卡在"请选择以下操作: [r]/[m]/[q]"那里不动
```
**预期输出**：
- 终止阻塞进程，禁止无限等待
- 说明原因（应用未拉起/日志未落盘），给出手动启动应用重试或手动拉取日志转本地模式的降级路径

### 测试场景 6：无设备
**提示词**：
```
设备好像没连上，直接帮我跑一下采集吧
```
**预期输出**：
- 不盲目重试，引导连接设备并开 USB 调试
- 提供转本地日志解析的替代路径
