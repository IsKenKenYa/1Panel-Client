# 智感旋转机制详解

> 智感旋转是窗口旋转的核心增强能力。本文说明其机制、生效条件、与旋转策略及旋转锁定的关系，以及应用侧接入方式。

## 什么是智感旋转

传统窗口旋转仅依赖**重力传感器**（Sensor 角度）判断设备握持方向。智感旋转在此基础上引入**智感传感器**：支持该传感器的设备（搭载 **OpenHarmony 7.0.0 及以上版本**），用户可通过 **设置 > 系统 > 智感旋转** 开启智感旋转开关。开启后，应用的最终显示方向由**重力传感器和智感传感器共同作用决定**，方向跟随更精准自然。

## 系统方向判定模型

系统综合以下因素决定应用的显示方向（智感旋转为 OH 7.0.0+ 设备新增因素）：

```
最终显示方向 = f(
  应用设置的旋转策略,          // setPreferredOrientation 或 module.json5 orientation
  设备当前握持方向,            // 重力传感器 Sensor 角度
  系统旋转锁定开关状态,        // 下拉控制中心查看/设置
  应用所处场景,                // 全屏/分屏/智慧多窗悬浮窗/自由多窗/后台等
  系统智感旋转开关状态          // OH 7.0.0+，支持智感传感器的设备
)
```

## 生效条件

| 条件 | 说明 |
| --- | --- |
| 系统版本 | OpenHarmony 7.0.0 及以上版本 |
| 设备硬件 | 支持智感传感器 |
| 用户开关 | 设置 > 系统 > 智感旋转，需用户开启 |
| 应用策略 | 自动旋转类策略、`FOLLOW_DESKTOP`，或未显式设置的默认 `UNSPECIFIED`（见下表） |
| 窗口/场景 | 仅主窗口 + 前台全屏；分屏/智慧多窗悬浮窗/自由多窗/后台场景被系统忽略 |
| 传感器 | 无重力传感器设备（TV 等）旋转策略本身不生效，智感旋转亦无从谈起 |

## 智感旋转与旋转策略的关系

**应用零代码改动即可接入智感旋转**：智感旋转不引入新接口，系统根据应用设置的策略类型自动决定是否启用智感参与判定。

| 策略类型 | 是否参与智感旋转 | 说明 |
| --- | --- | --- |
| 自动旋转方向类型（`AUTO_ROTATION` 系列 7 种） | ✅ OH 7.0.0+ 参与 | 最终方向由重力传感器和智感传感器共同作用决定 |
| 临时方向类型（`USER_ROTATION` 系列 4 种） | ✅ OH 7.0.0+ 参与 | 调用时立即临时旋转到指定方向，之后跟随传感器自动旋转（含智感传感器） |
| 固定方向类型（`PORTRAIT`/`LANDSCAPE`/`PORTRAIT_INVERTED`/`LANDSCAPE_INVERTED`） | ❌ 不参与 | 固定方向，不跟随任何传感器 |
| 跟随桌面类型（`FOLLOW_DESKTOP`） | ✅ OH 7.0.0+ 参与 | 应用跟随桌面方向；开启智感旋转的设备上，桌面方向判定融合智感传感器信号，应用随桌面获得智感体验（直板机桌面固定竖屏，方向不变化） |
| 未定义类型（`UNSPECIFIED`） | ✅ OH 7.0.0+ 参与 | 应用未显式设置策略时的默认值，由系统判定方向；开启智感旋转的设备上，系统方向判定融合智感传感器信号（直板机默认竖屏不可旋转，方向不变化） |
| 锁定类型（`LOCKED`） | ❌ 不参与 | 锁定模式，保持与前一应用相同方向 |

在支持智感旋转的设备上，`AUTO_ROTATION` 系列表现为：智感旋转开关开启时，方向判定融合智感传感器信号；开关关闭或设备/系统不支持时，自动回退为纯重力传感器判定。**应用侧一套代码即可覆盖全档位设备。**

## 智感旋转与系统旋转锁定开关

- 带有 "RESTRICTED" 字样的类型（`AUTO_ROTATION_RESTRICTED`/`AUTO_ROTATION_PORTRAIT_RESTRICTED`/`AUTO_ROTATION_LANDSCAPE_RESTRICTED`）受控制中心旋转开关控制：旋转锁定打开时，应用固定在锁定的方向，**既不跟随重力传感器，也不跟随智感传感器**（OH 7.0.0+ 行为）。
- `AUTO_ROTATION`/`AUTO_ROTATION_PORTRAIT`/`AUTO_ROTATION_LANDSCAPE`（不带 RESTRICTED）**不受**控制中心旋转开关控制，传感器（含智感）判定始终生效。

## 应用侧接入建议

1. **优先自动旋转类策略**：希望获得智感旋转体验（或方向跟随体验）的页面，使用 `AUTO_ROTATION_RESTRICTED`（跟随开关、四方向）或 `AUTO_ROTATION_UNSPECIFIED`；仅竖向/横向跟随用 `AUTO_ROTATION_PORTRAIT(_RESTRICTED)`/`AUTO_ROTATION_LANDSCAPE(_RESTRICTED)`。期望与桌面方向保持一致的应用（如桌面工具类）可用 `FOLLOW_DESKTOP`，同样参与智感旋转（注意直板机桌面固定竖屏）。未显式设置策略的应用默认 `UNSPECIFIED`，在系统允许旋转的设备（如平板）上同样参与智感旋转；直板机默认竖屏不可旋转，需显式设置自动旋转类策略才能旋转。
2. **视频类全屏切换**：进入全屏立即转横屏用 `USER_ROTATION_LANDSCAPE`，退出恢复自动旋转类策略，两者在 OH 7.0.0+ 设备上均支持智感旋转。
3. **避免用固定策略"模拟"旋转**：用 `PORTRAIT`/`LANDSCAPE` 硬切换会丧失传感器跟随能力，也就无法体验智感旋转。
4. **无需判断设备是否支持智感旋转**：系统自动处理，应用不感知。
5. **用户不开启开关时行为不变**：智感旋转开关由用户控制，应用无法（也不应）代为开启。

## 常见问题

**Q：智感旋转需要申请权限或调用新接口吗？**
A：不需要。设置自动旋转类策略、`FOLLOW_DESKTOP`，或保持默认 `UNSPECIFIED`（系统判定）即可，无新增权限、无新增 API。

**Q：如何验证智感旋转是否生效？**
A：在支持智感传感器的 OH 7.0.0+ 设备上，进入 设置 > 系统 > 智感旋转 开启开关，打开设置了 `AUTO_ROTATION_RESTRICTED` 等策略的应用，改变握持姿态观察方向跟随是否更精准。

**Q：智感旋转开关和旋转锁定开关同时开启会怎样？**
A：若应用使用 RESTRICTED 类策略，旋转锁定优先：固定在锁定方向，重力与智感传感器均不跟随；若使用不带 RESTRICTED 的 `AUTO_ROTATION` 系列，旋转锁定开关不影响该应用。
