# 场景判断规则

> 对应规格 R-1 / R-2 / R-3。用于判断开发者描述的场景是否需要使用命令式节点。

## 概述

命令式节点（BuilderNode / FrameNode / RenderNode）提供了脱离声明式 `build` 方法动态创建和管理节点树的能力。但并非所有场景都需要命令式节点——当声明式构建可满足时，使用命令式节点属于滥用，会增加复杂度和维护成本。

本文件定义三条场景判断规则，按开发者描述的关键特征匹配，输出"建议使用"或"不建议使用"的结论及判断依据。

---

## R-1: 动态增删组件场景 → 建议使用命令式节点

**触发条件描述：** 开发者需要在运行时动态增删组件，或将节点树灵活挂载到不同父节点下，且这种操作发生在 `build` 方法执行之外（非声明式重建）。

**判断依据：** 声明式范式（`build` 内的 `ForEach` / `LazyForEach` / `if-else`）在数据变化时会触发组件树的销毁与重建，无法将一个已创建的节点树在不同父节点间迁移复用。命令式节点（BuilderNode/FrameNode）持有独立的实体节点引用，可通过 `appendChild` / `removeChild` / `moveTo` 在运行时改变挂载位置，无需重建组件树。这是命令式节点的核心场景。

**示例场景：**
- 第三方框架（JSON/XML/DOM 树驱动）需将 DSL 转换为 ArkUI 节点树并动态操作。
- 需要将同一个组件树在不同页面或不同容器间迁移显示（如跨 NodeContainer 复用）。
- 运行时根据业务条件将节点从一个父节点移除后挂载到另一个父节点（使用 FrameNode `moveTo`）。
- 需要在 `build` 之外响应用户操作动态插入/移除节点。

**匹配关键词：** 动态挂载、运行时增删、节点迁移、moveTo、跨容器复用、DOM 操作。

---

## R-2: 预创建组件场景 → 建议使用 BuilderNode

**触发条件描述：** 开发者需要提前创建组件以优化初始化耗时，即在真正需要显示之前完成组件创建和资源加载，后续再动态挂载显示。

**判断依据：** 声明式组件在 `build` 执行时创建，创建时机由组件树渲染流程决定，开发者无法控制。BuilderNode 可在任意时机（如应用启动时、页面预加载阶段）调用 `build(wrapBuilder(...), params)` 创建组件树，后续通过 `getFrameNode()` 挂载到 NodeContainer 显示。这种"先创建后挂载"的模式能有效减少首次显示耗时。尤其适用于 Web、XComponent 等初始化耗时较长的组件——预创建虽然不能减少组件本身的创建时间，但可以让内核提前加载资源，减少正式使用时的加载耗时。

**示例场景：**
- 预创建 Web 组件，让内核提前加载资源，后续挂载时减少加载耗时。
- 预创建 XComponent，提前初始化渲染管线。
- 页面预加载：在用户进入页面前创建好组件树，进入时直接挂载显示。
- 需要控制组件创建时机的场景（声明式创建时机不可控）。

**匹配关键词：** 预创建、预加载、优化初始化、提前创建、减少耗时、Web 预热、XComponent 预初始化。

---

## R-3: 声明式可满足场景 → 不建议使用命令式节点

**触发条件描述：** 开发者描述的场景可以在 `build` 方法内通过声明式构建方式满足，包括 `ForEach` / `LazyForEach` / `if-else` / `@Component` / `@Builder` 等声明式能力。

**判断依据：** 声明式范式已提供条件渲染（`if-else`）、列表渲染（`ForEach` / `LazyForEach`）、组件复用（`@Reusable`）等能力，能覆盖绝大多数动态 UI 需求。命令式节点引入额外的实体节点引用管理和手动生命周期管理（dispose），增加内存泄漏风险和维护成本。当声明式可满足时使用命令式节点属于滥用。仅当声明式确实无法满足（如需跨父节点迁移已创建节点、需脱离 build 生命周期预创建）时才建议使用命令式节点。

**示例场景：**
- 根据数据动态显示/隐藏组件 → 用 `if-else` 即可，不需命令式节点。
- 列表数据变化动态增删列表项 → 用 `ForEach` / `LazyForEach`，不需命令式节点。
- 组件复用 → 用 `@Reusable` 装饰器，不需命令式节点。
- 条件切换显示不同内容 → 用 `if-else` 或 `@Builder`，不需命令式节点。
- 需要延迟创建组件但无跨容器迁移需求 → 用 `if` 条件控制即可。

**匹配关键词：** 条件显示、列表动态、if-else 可实现、ForEach 可实现、LazyForEach 可实现、组件复用。

---

## 判断流程

```
开发者描述场景
    │
    ├─ 需在 build 之外动态增删/迁移节点树？ ──是──→ R-1: 建议使用命令式节点
    │        │否
    ├─ 需提前预创建组件优化耗时？ ──是──→ R-2: 建议使用 BuilderNode
    │        │否
    ├─ build 内 ForEach/LazyForEach/if-else 可满足？ ──是──→ R-3: 不建议使用命令式节点
    │        │否
    └─ 需进一步分析具体需求，考虑命令式节点
```

## API 版本要求

- BuilderNode / FrameNode / RenderNode 基础能力：API 12+
- FrameNode `moveTo`（节点迁移）：API 18+
