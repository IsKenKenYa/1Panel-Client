# 测试用例 5："为什么没触发"排查（系统侧判定链路）

## 场景描述
真机半折叠后悬停回调始终不触发，开发者怀疑接口坏了，需要系统侧判定链路排查。

## 前置条件
- 已按标准 API 接入并注册 `onWindowPostureModeChange`
- 测试设备为折叠屏
- 可执行 hidumper 命令（验证阶段）

## 执行步骤
1. AI 代理识别任务落点为触发排查（场景 HVS-01），按系统侧判定链路逐项排查：
   - 窗口是否全屏模式 + 全屏尺寸（分屏/悬浮/自由窗口不进入）
   - 是否无 transform 缩放、非 LS 态
   - 折痕是否横向（书本型设备竖屏半折叠属预期不触发）
   - 是否分离架构（恒返回 false）
   - 注册时是否传了 `WindowPostureMode.DESKTOP_MODE`（实例方法形态）
2. AI 代理给出 hidumper 模拟折叠形态的验证命令（仅验证阶段使用）
3. AI 代理明确应用侧只消费状态、不反向修改系统判定的红线

## 预期结果
- 排查覆盖系统侧判定链路的全部条件项
- 竖屏半折叠不触发被解释为预期行为（折痕方向性），不误导为 bug
- 不建议用系统参数/hidumper 改设备状态来"凑"悬停效果

## 验证方法
- 检查输出是否包含窗口条件清单（全屏、缩放、LS 态、折痕方向、架构门控）
- 检查是否给出 hidumper 验证命令且限定验证用途
- 真机/模拟器：分屏下确认不触发、转全屏后确认触发

## 备注
排查结论应对齐 wms-internals.md 的判定链路描述，不臆造系统行为。
