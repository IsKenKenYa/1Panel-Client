## 1. 判定总览

NAPI 模块（.so）被 dlopen 后，TopLevel C++ 代码立即执行：constructor 注册函数、`napi_module_register`、注册回调 `nm_register_func`、C++ 全局静态对象构造——不等 ArkTS 调用导出函数。注册链中的业务动作与加载期初始化直接计入启动路径。

两类候选：
1. **类别1**：注册函数违规业务逻辑——注册链中与 exports 无关的业务动作（S-01 锚点）；
2. **类别2**：加载期重初始化——so 加载即执行的初始化（形态A 文件作用域 / 形态B 注册链赋值 / 形态C 注册链创建）。

```
候选（信号命中/初始化器——仅是候选线索，成本必须独立按 S-07/S-08/S-09 定级，禁止直接定性）
→ S-07/S-08/S-09 成本三级（轻量=不计即结案；公开通用 API 按速查表直判；不可判定=待人工确认）
→ 成本=重 → S-24 归属门控（在路径=需整改【机械途径 M-27 T1/T2】；待核=需确认；范围外=附注）
→ UNRESOLVED/非公开外部符号/归属存疑（S-20）→ 待人工确认（禁止静默判 OK）
→ 整改方向按位置映射（S-17/S-18/S-19）
```

**复核信息边界（P-06）**：语义判定只依据底稿/分片内联信息——**禁止回读源文件**；例外仅 3 项：归属存疑项核对定义、UNRESOLVED 的 include-follow（M-17）、外部符号成本定位。

## 2. S 层：语义判定规则

### S-01 类别1 锚点
- **规则**：与构建 exports 无关——删除该段代码后 exports 构建完全不受影响 → 类别1 候选。命中仅代表候选；成本按 S-07~S-09 定级。

### S-02 类别1 典型动作族

| 动作族 | 复核要点 |
|---|---|
| 信号/事件处理器注册 | `signal`/`sigaction`/`Register*Callback`/`napi_set_promise_rejection_callback`/事件循环 attach——dlopen 即改变进程行为 |
| 线程操作 | 创建/join/detach——**一律判重**（S-07） |
| 进程级全局注册 | 向进程级 registry/manager 注册本模块、创建全局单例 |
| 外部服务/IPC | SAMGR 代理获取、同步 IPC、外部服务调用 |
| 其他业务动作 | 初始化业务服务、读配置文件、上报——与构建导出面无关即命中 |

- **边界**：动作实现定位不到 → 不可按清单直接定性（S-06）；机械信号表（M-19）仅为本表子集，清单外动作靠语义复核发现。
- **候选 ≠ 结论**：**S-02 动作族与 M-19 信号命中只是候选线索，不是成本结论。**每个命中必须独立走 S-07/S-08/S-09；`signal`/`sigaction` 若实现仅为函数指针/回调槽赋值 + 栈上 POD + 系统调用，按 S-08 定档口径① 与 S-09 速查表判**轻量**，不得以“改变进程行为/影响面大”为由判重（成本轴是加载耗时，不是风险影响面）。

### S-03 排除：导出面构建
- **规则**：`napi_property_descriptor` 声明与挂载、`napi_create_function`/`napi_define_class`/`napi_set_named_property`/`napi_wrap`/`napi_get_cb_info`/`napi_create_object`、挂到 exports 的对象创建、`return exports` → 不算类别1。
- **边界**：/exports 标记（M-23）存在行段混叠（仅覆盖相邻行）——不得据此静默排除。

### S-04 状态建立归类别2
- **规则**：构造对象/获取资源/建连接 → 归类别2，按 S-07~S-09 判成本。

### S-05 检测范围
- **规则**：＝注册链（constructor/回调/被调函数）＋ 加载期初始化代码（文件作用域初始化器、被创建对象的构造函数体）——业务动作藏进初始化器同样命中类别1。

### S-06 动作实现定位必做
- **规则**：定位动作的**实现函数体**（底稿提供或人工跟进）；定位不到 → 实现不可见 → 待人工确认（S-09；公开通用 API 例外见其速查表）。

### S-07 成本·重
- **规则**：天然耗时类：**线程操作（创建/join/detach）**/文件 IO/网络连接/外部服务调用（IPC/SAMGR）/`dlopen` 其他库/大内存/预编译表/非平凡计算；或实现可见且判定耗时 → 执行 S-24 归属门控。

### S-08 轻量 → 不计问题（即结案）
- **规则**：实现可见且为以下形态 → **不计问题、即结案、不做归属确认**：常量、编译期可计算值、小对象/POD 构造、置标志、无 IO 纯内存操作/记账、函数指针赋值级注册。
- **定档口径①**：`signal`/`sigaction`/`Register*Callback`/事件循环 attach 按实现语义定级——仅函数指针/回调槽赋值（含栈上 POD 构造与记账）→ 本条；实现含文件 IO/线程/IPC/大内存 → S-07。动作族命中不代表重档。**注意：E-15（fix-patterns §8.10 保留信号第三出口）属阶段 2 整改语句分流，扫描阶段按本条+速查表直判轻量即结案，不影响阶段 1 判定。**
- **定档口径②**：构造函数体未内联，但满足 ① 无参/默认构造（或实参为纯常量）＋ ② 构造体所在文件**全文信号扫描干净**（构造体与候选同文件时，深析信号扫描已覆盖之）→ 轻倾向成立，按本条**轻量结案**（附注"构造体经全文信号扫描覆盖"）；不满足（有参构造且实参含调用／构造体在未扫描文件）→ S-09 待确认。

### S-09 不可判定 → 待人工确认（公开通用 API 除外）
- **规则**：动作/初始化器经**非公开通用**外部符号/间接调用、定义不可见（如 `SystemAbility::MakeAndRegisterAbility`、`OHOS::system::GetParameter` 等平台/厂商仓外 API——成本无法从公共语义推断）→ **待人工确认，禁止静默判 OK**；归属确认列为可选复核要点（确认范围外可结案为范围外附注）。**函数名不构成实现可见性证据**——禁止从命名（如 `create_*`/`init_*`/`register_*`）推断成本档位或违规类别而直接判需整改；定义不在检查范围即按本条待人工确认，输出 `⏳ 需确认` 并给出「定位实现函数体后按耗时定级」复核建议。
- **公开通用 API 例外（方案A11）**：C++ 标准库 / C·POSIX 运行时 / 语言级原语——成本属**公共语义常识** → 按下方速查表**直接定级**（可轻可重——公开 ≠ 轻量），**不转人工确认**。速查未收录且成本可从标准语义可靠推断 → 同样直判；推断不可靠 → 仍待人工确认。**平台/厂商 API（OHOS inner、三方闭源库）不适用本条**——即使有公开文档，实现成本仍需查证（如 `GetParameter` 适配器可能 dlopen+IPC）。

**公开 API 成本速查表（公共语义直判，双向；高频条目，实战验证后追加）**：

| API | 公共语义成本 | 定级 |
|---|---|---|
| `std::chrono::*::now` / `clock_gettime` / `time` | vDSO 时钟读，µs 级以下 | 轻量 |
| `getenv` / `setenv` / `putenv` | 环境表查找 | 轻量 |
| `sigaction` / `signal` | 系统调用，µs 级静态有界 | 轻量 |
| `pthread_once` ＋ `pthread_key_create` | TLS 键创建 | 轻量 |
| `std::string` 字面量构造 / 标准容器默认构造 | SSO / 空容器 | 轻量 |
| 小额 `malloc` / `new`（KB 级） | 堆分配记账 | 轻量 |
| `std::regex` 构造 / `assign` | **正则编译**（NFA/DFA 构建，非平凡模式可达 ms 级） | **重** |
| `std::thread` 构造 / `pthread_create` | **线程创建** | **重** |
| `fopen` / `open` / `ifstream` 构造 | **文件 IO** | **重** |
| 大额堆分配（≥MB 级） | 立即触碰全页/清零 | **重** |

### S-10 灰区裁决
- **规则**：① 纯内存且规模静态有界 → 轻倾向；② 规模依赖运行时数据（循环次数/容器大小由配置决定）→ 重倾向；③ 含外部依赖（内存映射/运行时服务查询）→ 重；④ 仍无法裁决 → 待人工确认。

### S-11 [已废弃 2026-10-29：参数读取单列移除——非通用准则]
- 参数读取回归通用判定：外部符号、实现不可见 → S-09 待人工确认。编号废弃保留，不复用。

### S-12 判定原则
- **规则**：按动作/初始化器**实现语义**定级；定义在其他文件时经 prescan 定位/include-follow 找到实现后按函数体判定；找不到 → 不可判定（待确认）——**公开通用 API 例外：按 S-09 速查表/公共语义直接定级，不转人工确认**。

### S-13 宿主：call_once 不改归属
- **规则**：`call_once`/`once_flag` 不改变宿主归属——包裹的初始化仍随宿主函数执行；宿主在注册链上＝加载期执行。once_flag 保证进程级仅首个触发模块实际执行，其余命中为空过（标志检查级成本）。

### S-14 宿主：全局赋值宿主必须显式确认
- **规则**：`g_x = ...` 出现在哪个函数里必须实际确认——宿主＝注册回调或其调用链 → 类别2 候选；普通导出函数内（首次调用才执行）→ **不算 import 副作用**。禁止按"看起来像运行时回调"推断归属。

### S-15 宿主：类内成员分流
- **规则**：`static` 数据成员初始化属加载期——收集并标注"类内静态成员"；非 static 成员初始化随对象构造 → 归构造链判定。

### S-16 同名归属存疑标注
- **规则**：同名函数解析可能误归（定义文件与调用模块明显无关）→ 标注"归属存疑，建议人工核对"。

### S-17 整改·形态A
- **规则**：文件作用域（形态A）→ 惰性初始化（首次使用时，如函数内 static 局部）。

### S-18 整改·形态B/C
- **规则**：注册链内赋值/创建（形态B/C）→ 移至业务首次初始化（单一入口如应用初始化入口/显式 init 导出函数，**保持单例状态一致**）。

### S-19 整改·非静态全局
- **规则**：external linkage → 附注：评估可否收窄 `static`；不能收窄则警示惰性化可能造成外部编译单元上下文不一致，需人工评估。

### S-20 边界：非公开外部符号/UNRESOLVED/间接调用
- **规则**：初始化器/动作为**非公开通用**外部符号（公开通用 API 按 S-09 速查表直判）、UNRESOLVED 回调、经函数指针/虚调用 → 待人工确认（禁止静默判 OK）。

### S-21 边界：构造函数体内业务动作
- **规则**：构造函数体内含业务动作（信号/线程/事件循环/进程级注册）→ 归类别1 候选（S-01 锚点），按 S-07~S-09 判成本。

### S-22 边界：构造函数体内仅资源获取
- **规则**：构造函数体内仅资源获取（建连接/分配/读配置）→ 状态建立 → 类别2 按成本判定。

### S-23 边界：挂到 exports 的业务对象豁免
- **规则**：挂到 exports 的业务对象（经 `napi_wrap`/属性挂载）→ 导出面构建一部分——注册期必须存在，**不计问题**；构造本身耗时最多附注提示。
- **边界**：构造或构造参数含天然耗时类动作（S-07 类）时**仍按本条豁免**——附注提示为报告要求输出（不强制整改）。

### S-24 归属门控（仅成本=重时执行）
**判定顺序**：成本先行、归属惰性——轻量即结案（S-08，跳过本条）。

| 归属状态 | 判定依据 | 重档结论 |
|---|---|---|
| ① 确认在 import 路径 | `nm_modname` 自注册 / GN deps 链含该库且打包进应用 / `readelf -d` DT_NEEDED 实证 / M-27 归属 T1、T2 | ❌ **需整改** |
| ② 待核 | 静态分析无法确认（基础库/innerkit/服务库，无构建图可达） | ⏳ **需确认（归属优先）**——禁止直接判需整改；复核要点给升级路径 |
| ③ 确认范围外 | sa_profile 纯服务 so / 仅服务进程链接 | 范围外附注（非 import 路径，不计问题） |

- 不可判定项（S-09）的归属确认为可选复核要点（确认范围外可结案附注）。

## 3. R 层：报告契约

### R-01 报告结构与判定轨迹
`📊 报告` → 一、总结 → 二、问题明细（类别1→类别2→待人工确认）→ 三、模块结论汇总＋整改清单 → 四、文件结论清单（按 R-10 五档分组）→ **五、判定轨迹（简版）**——三段式：①扫描完整性一句话（追深截断与否＋双不变量对账）；②待确认项卡点每项 2~3 行（项名＋定位＋为什么定不了＋人工要做什么——批量例外核查的簇记录压缩于此，四要素不丢：对象/定位/结论/影响）；③其余结论一句话（干净链抽查/整体评价）。规则 ID 降为**可选末行锚点**。完整模板见 §3.10。

### R-02 明细条目格式（白话判定原因）
`📍 文件:行号（合并条目取最小连续覆盖区间）`＋代码片段＋`⚠️` **判定原因（面向开发者的白话）**——该操作在模块加载时做了什么、为什么耗时/轻微/无法确认、本模块是否被应用加载、对启动的影响＋`💡` **整改建议（白话）**——把什么移到哪里、为什么能消除影响。待确认用 `❓` 原因（白话）＋`👉` 建议核实步骤（白话）＋`🔎` 加载路径确认（仅耗时且归属不明条目必填）。
**四段正文禁止出现规则 ID／文档引用**——按 §3.11 对照表翻译；规则 ID 仅可作为判定轨迹末行的可选锚点（审计回查用）。
**导出面构建排除说明（S-03）**：注册回调内的 `napi_get_undefined`/`napi_wrap`/`napi_set_named_property`/`napi_define_properties`/`napi_create_function` 等属导出面构建（S-03），不计为副作用——报告须显式说明此类调用已排除复核，不得静默跳过。

### R-03 三档结论映射（成本 × 归属二维）
- 含耗时发现（重）**且归属确认在 import 路径**（含 M-27 T1/T2 机械确认）→ ❌ 需整改；
- 含耗时发现但归属待核；或仅存在不可判定条目 → ⏳ 需确认（归属优先——确认在路径后升级需整改，确认范围外结案附注）；
- 全部干净/候选均轻量；或耗时发现经确认范围外（附注说明） → ✅ NAPI OK。
判定顺序：成本先行、归属惰性（S-24）。**T1/T2 文件的重档发现直接判需整改**。
**档位 token 强制输出**：模块结论与文件结论**必须原样输出规范档位 token**——`❌ 需整改`/`⏳ 需确认`/`✅ NAPI OK`；**禁止用自然语言改写**（如「未发现副作用」「干净模块」「无问题」等替代「✅ NAPI OK」）。干净模块的结论段必须出现字面 token `✅ NAPI OK`。

### R-04 单调汇总
档位优先级 需整改 > 需确认 > NAPI OK；文件结论＝全部发现最高档（空发现 → OK）；模块结论＝关联文件最高档；需整改/需确认模块必须列文件并回指问题编号（#n）。

### R-05 相邻合并
同文件**同类别**、行号连续或同函数体间隔 ≤3 行（中间无其他类别穿插）→ 合并一条；行号取 `[first, last]`；片段取最小连续区间；**计数＝原子发现数（合并不改变计数）**；不同类别不合并。

### R-06 大仓瘦身（模块 > 40 时必须）
① 文件结论清单不逐一罗列 OK 文件——按组件分组计数；② 问题明细只列需整改/需确认。

### R-07 落盘询问话术
报告完整输出后主动询问："是否需要将本次检查报告保存为 markdown 文件？如需要，请提供输出路径。"；默认不落盘；同意未给路径 → 追问。写入是唯一允许的写操作，且仅在用户确认后。

### R-08 单文件模式注记（E-4）
单文件输入按文件粒度报告；模块汇总段注明 `单文件模式：无模块上下文，未按 napi_module 汇总`。

### R-09 边界输出格式（E-1/E-2）
E-1 → `❌ 路径不存在：<path>，请检查后重试`（不产报告）；E-2 → `未发现 NAPI 相关代码`＋扫描统计，无问题条目。

### R-10 模块归属分组

### R-11 动作链合并
- **规则**：同一业务动作经调用链展开**连通且实现体已定位验证**（追深覆盖或例外核查确认链边）→ 跨文件合并为**一条**问题条目：根锚定在**注册链最早触发点**（整改可执行位置，S-18 对应），链上实现体（proxy/转发体）作为成本证据随条承载、**不独立计数**；各文件:行列入条目，原子计数保留。
- **边界**：仅猜测边连通（S-16 未核）→ **不合并**，各条独立并保留存疑标注；共享的通用封装（如 IPC 发送 helper）不得作为独立条目锚点——其整改不可在自身执行。

## 4. M 层：机械发现规则

> 正则与参数的**实现权威＝scripts/prescan.py**；本层载全部 M 规则的**语义本体**（agent 复核时的消费语义）。带「agent 执行」标注的条目由 agent 复核时执行；其余由 prescan 机械执行、agent 消费其输出。实现锚点见 §4.7。

### 4.1 路径过滤（M-01~M-03）

**M-01 后缀白名单**：仅 `.cpp`/`.cc`/`.cxx`/`.c` 实现文件为扫描目标；头文件（.h/.hpp）不是扫描目标，但作为深析的**解析对象**（M-17）。

**M-02 排除目录段（段精确匹配）**：路径任一目录段精确命中 `test/tests/example/examples/sample/samples`（大小写不敏感）默认跳过；`--all` 取消排除（后缀白名单仍生效）。

**M-03 隐藏目录跳过**：目录名以 `.` 开头 → 跳过。

### 4.2 注册链要素（M-04~M-09）

**M-04 constructor 注册要素**：模式 `__attribute__\s*\(\(\s*constructor\s*\)\)`——捕获 so 加载即执行的注册函数（dlopen 副作用第一入口）。**引号遮蔽预处理**（mask_quotes）先于要素检索与信号匹配：字符串/字符字面量整段替换为等长空格（含引号；处理 `\"`/`\'` 转义；未闭合遮蔽至行尾；等长保持 P1-P4 列首锚定）——跨 M-04~M-09 与形态A信号生效；`nm_register_func`/ctor 名解析在遮蔽文本上进行，`.nm_modname`/`NAPI_MODULE` 宏解析仍用原文。

**M-05 注册点要素（三词形）**：模式 `\b(napi_module_register|napi_module|nm_register_func)\b`——同一注册点的三个词形症状（**调用点/结构体/回调字段**），可拆分在不同文件或头文件；`\b` 词边界使 `napi_module` 不误命中 `napi_module_register` 等前缀扩展词形。M-06/M-07 已废弃并入本条（编号保留不复用）。

**M-08 NAPI_MODULE 注册宏**：模式 `\bNAPI_MODULE\w*\s*\(`（宽模式，`\w*` 补获 `NAPI_MODULE_XXX` 变体）。**边界**：`REG_NAPI_MODULE` 前缀形态不在检测范围（`\b` 前缀边界不可达；如需检测须扩展模式）。

**M-09 变体注册点**：模式 `\bnapi_module_with_js_register\b` / `\bNativeModuleManager\s*::\s*Register\b`——命中时标注"**需甄别注册方/运行时使用方**"。

### 4.3 形态A 信号与排除（M-10~M-14、M-25、M-26）

**共同前提（M-10~M-13）**：OHOS 仓 `.clang-format` 规定 `NamespaceIndentation: None`——文件作用域声明必然**列首**开始、函数体语句必然**缩进**，列首锚定由此获得机械排除力。

**M-10 P1 列首声明式**：`= new/call(...)` 初始化，限定符/static/inline/const/volatile 可选；`constexpr`/`constinit` 整行排除（静态初始化）。

**M-11 P2 直接初始化**：`Type name(args);`——变量名小写启发式区分 PascalCase 函数声明；行尾 `;`（定义首行永不以 `;` 结尾）；残余误报经 M-25 预剔除＋深析兜底。

**M-12 P3 类外静态成员定义**：`Type Class::member = new/call(...)`。

**M-13 P4 安全网（默认关，`--safety-net` 开启）**：缩进 static/inline——命中必做作用域确认（剔除函数局部 static）。

**M-14 形态A 排除管道**：模式 `^(using|typedef|extern)\b` ｜ `=\s*(sizeof|alignof|offsetof|decltype|noexcept)\s*\(` ｜ `^(static\s+|inline\s+)*void\s+[a-z_]\w*\s*\(`——命中的行不计形态A候选。

**M-25 P2-proto 原型预剔除**：P2 命中行若**全部参数段**（逗号切分）均为带名形参形态（`Type name`/`Type *name`/`Type* name`）→ 标注 `P2-proto`，**不计形态A候选**；统计单列＋独立输出段（不静默丢弃）。保守条件（不判即保留候选，由语义层裁决）：参数段含 `(` `)` `"` `'` `{` `}` `=` `<` `>`、空参/`void`/单词参数（most vexing parse 不可解）、`*`/`&` 未贴附一侧（乘法与形参词法同形）。

**M-26 P1ns/P2ns ns 区域缩进信号**：缩进的命名空间作用域全局由深度状态机收割为形态A候选——**收割条件四合一**：① ns 内容层（花括号深度 == 开区深度+1，精确排除 ns 内函数体）② 行缩进（顶格 ns 内容由 M-10/M-11 覆盖——两网按是否缩进分界，**不相交、并集完整**）③ 行内无花括号（排除单行函数体）④ P1ns（`= new/调用`）/ P2ns（直接初始化）形态。开区识别：`namespace {`/`namespace foo {` 同行或跨行 `'{'`（inline 前缀支持；别名 `namespace x = y;` 与 `using namespace` 天然不匹配）；深度回落至开区层即闭区；**宏续行**（行尾 `\` 的 `#` 指令延续）对深度记账与收割均不可见；无 ns 开区的文件整文件跳过（预门）。排除管道与 P2ns 原型疑例通道同 M-14/M-25。残余漏检：单行 ns 块、同行嵌套开区、带属性 ns。

### 4.4 回调与符号解析（M-15~M-17——agent 执行）

**M-15 注册回调解析（禁止命名惯例）**：回调名**必须从注册点解析**——`.nm_register_func = <回调名>`（含跨行字段；字段可位于头文件，经 M-17 解析）或 `NAPI_MODULE(模块名, <回调名>)` 宏第二参数；**禁止按命名惯例（`Init(` 等）猜测**——回调可为任意名字（InitHttpModule/Export/CloudSyncExport/`Class::Method`…）。prescan 自动完成定位（本文件/跨文件/头文件 include-follow/UNRESOLVED）＋函数体提取（含变体注册点标记与 nullptr 过滤）。

**M-16 UNRESOLVED 边界**：UNRESOLVED 回调 → 待人工确认或 include-follow 闭环，**禁止静默跳过**（输出显式列表）；处理结果必须进入报告。

**M-17 符号解析（include-follow）**：被引用但已扫描实现文件中无定义的符号 → 沿 `#include` 头文件检索定义；头文件为**解析对象**而非扫描目标（不进漏斗统计，发现归因到包含方实现文件与模块）；典型覆盖：头文件 `inline` 变量动态初始化、头文件 `static` 全局、`static inline` 成员初始化；**限定名须在定义文件中全串出现（防同名误归）**；同类归属可疑 → 标注"归属存疑"（S-16）；仅有声明或检索不到 → 待人工确认。
- **注册点字段头文件解析**：本文件含注册点要素（M-05）但无 `.nm_register_func` 时，沿 `#include "..."` 解析头文件字段——解析顺序：① 同级目录/`../include`/`../../include`（OHOS GN include_dirs 惯例）→ ② **全树唯一 basename 兜底**（歧义即跳过，防跨组件同名头文件误归因）；限深 2；发现归因到包含方（来源标注含头文件名）。
- **边界**：单文件输入模式 header 索引为空（include-follow 仅本地候选生效）。

| 系统参数读取 | `\bsystem::Get\w*Parameter\s*\(` |
| 应用上下文 | `\bGetApplicationContext\b\|\bCreateModuleResourceManager\b` |

**消费边界**：① 应用仓域层真阳性预期为零（inner kit 不可链）——词形通用成员误报剔除；② `SIG[A-Z]{2,}` 可命中枚举键名——非信号注册时剔除；③ 信号扫描未做引号遮蔽——日志字符串可伪命中——剔除（方向安全）；④ 注册动词族为命名公约启发式——非公约命名注册动作漏检仅损失候选。

**M-20 调用链展开（默认全展开）**：`--deep` 机械展开调用链（深度默认 auto，自然饱和或上限 4）；**自由函数/限定名调用无条件展开候选**（CALLEE_RE，仅 CALLEE_SKIP 滤噪）；**方法调用默认全展开**；`--strict-expand` 可回滚生命周期命名白名单门控（`^(Load|Init|Create|Start|Setup|Register|Open|Connect|Prepare|Warm|Preload|Initialize|Deinit|Shutdown|Attach|Enable|Subscribe)[A-Z_]`）。
- **同名消歧标注**：跨文件解析命中多候选文件时节点标注 `⚠️ 同名候选 N 处（接收者类型未知，按目录邻近选取——复核需核对接收者）`——猜测边从静默变可见；本文件定义/限定名全串过滤唯一 → 恒信不标注；N 为候选文件数含仅提及者（保守上界）。**复核消费**：带同名标注的节点需核对接收者类型后方可采信其归属。
- **预算**：DEEP_SCAN_CAP 8000（信号扫描/被调提取按全文，截断即双失）；RENDER_CAPS (2400,1600,1200,800)（仅渲染）；CALLEE_CAPS (30,20,12)；MAX_NODES 2000（budget_exhausted 诊断）；AUTO_DEPTH_CAP 4。

**M-21 函数体提取上限**：`--max-body N`，默认 3000 字符/函数体。

**M-22 自动分片**：命中链 ≥10 或底稿总字节 >40KB → 自动分片；片数 = `max(1, min(8, (段数+7)//8))`，再 `min(片数, 10)` 封顶；**贪心装箱**（按段大小降序、放入当前最小片）；`--split 0` 强制内联；分片目录默认 `./prescan_shards`（当前工作目录）。**随片内容**：复核规则头后随附「本片文件归属（M-27）」档位行；渲染层去重（同体节点与重复命中行/函数体不再双份）。

**M-23 /exports 导出面标记**：模式 `\bnapi_(property_descriptor|create_function|define_class|set_named_property|wrap|get_cb_info|create_object|define_properties)\b|\bDECLARE_NAPI\w*\b`——命中行 → 深析按"导出面构建排除"复核（S-03 的机械锚点）。**边界**：标记仅覆盖相邻行（行段混叠）——复核不得据此静默排除。

**M-24 形态B·链内全局赋值（词法符号表四路路由）**：链内全局赋值由**词法符号表路由**判定（掩蔽节点体上匹配）：
- **R1 限定名**（`A::b =`，语言规则恒真，跳过局部检查）→ 全局赋值候选；
- **SIMPLE_ASSIGN**（简单名＋可选数组下标＋重形态 RHS；负向后行排除 `obj.m=`/`p->m=` 成员赋值）→ **R3 局部排除**（先于查表：起点锚＋语句关键字负向前瞻＋类型形 token＋声明终结符——C++ 内层遮蔽外层）→ **R2 本文件表命中**（附定义行）→ **R2h 头文件表**（本文件直接 `#include "..."` 限深 1，解析序同 M-17）→ **R4 表外待确认**（低置信候选；`g_/s_` 前缀附「命名先验，优先复核」**排序标注，不参与路由**）。
- **per-file 词法表**（build_symbol_table）：列首声明（文件作用域＋ns 顶格内容）＋ns 内容层缩进声明（共享 M-26 ns 状态机语义）＋类外静态成员定义＋extern＋多声明符逐段收名。**表盲区 → R4 兜底**（花括号初始化声明/多行声明/类内静态成员声明——失败方向安全：多候选，不静默）。
- **边界**：R2h 限深 1（间接包含头文件全局 → R4）；R3 漏检多声明符第二项/结构化绑定 → R4（安全）；`a = b = foo()` 链式赋值仅捕获末段。

### 4.6 模块归属（M-27——agent 消费）

**M-27 模块归属启发式（五档）**：对漏斗命中文件（链要素/形态A/P2-proto/安全网/链节点）判定归属的 NAPI 模块，优先级 **T1 定义**（自身 `nm_modname`——字符串或常量标识符（同文件解析 `X = "..."`，`#define` 保守跳过）；含头文件解析；或变体注册 `NativeModule` 的 `.name` 字段——门控用结构体类型名，对象形态 `moduleManager->Register(...)` 不命中限定要素）＞ **T2 链上**（模块注册链节点文件：level-0 根节点（ctor/回调定义文件）恒信；同名展开节点要求与注册文件公共路径 **≥2 级**）＞ **T3 同目录**（严格 dirname 相等，推测）。

**护栏**：① 命中 **>3** 个模块链 → 不确定（公共层/同名误归）；② 链上但**跨组件路径**（公共路径 <2 级）→ 不确定（同名解析污染）；③ 同目录多模块 → 不确定；④ 目录无注册文件 → **无归属**（非模块库文件）。

**消费规则（S-24 联动）**：

| 档位 | 语义 | 重档处理 |
|---|---|---|
| 定义（T1） | 自身注册 NAPI 模块 | 在 import 路径 → **需整改** |
| 链上（T2） | 注册链节点文件 | 在 import 路径 → **需整改** |
| 同目录(推测)（T3）/不确定/无归属 | 归属待核 | **需确认（归属优先）** |

- T1/T2 重档直接判需整改（R-03 联动），无需人工归属核查。未启用 `--deep` 时 T2 缺席（清单标注）。
